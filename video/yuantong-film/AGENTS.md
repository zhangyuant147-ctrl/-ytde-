# 视频制作规则：安全区、画面与导出

本文件适用于本目录及子目录中的视频项目，包括 Remotion 项目。制作和修改视频时必须遵循以下规则。

使用时应在 Codex 中打开此目录作为工作目录。若视频代码位于其他目录或独立 Git 仓库，应将这些规则放入该项目根目录的 AGENTS.md；已存在文件时合并规则，不能覆盖其他项目约定。不要假定放在一个目录里的文件会自动作用于其他项目。

## 1. 默认原则

- 开始排版前确定画幅、分辨率、发布平台，以及普通内容或广告版位。沿用用户已给出的信息；未指定平台时使用下方项目默认值，不为此反复询问。
- 区分两类安全区：防止显示裁切的「主体/动作安全区」，以及保护标题、字幕、Logo、联系方式和关键数据的「文字安全区」。短视频还须避开平台界面遮挡区。
- 背景、纹理和非关键信息可铺满画布；人物面部、关键产品和完整文字必须在各自安全区内。人物身体可以有意裁切，但面部和关键动作不能被意外切断。
- 本文所有边距均指从完整画布对应边缘向内量的距离。上、下百分比以高度计算，左、右百分比以宽度计算。
- 「文字安全区为中央 80%」表示左右各留 10%、上下各留 10%，不是四边各留 20%。
- 已核实的平台具体版位规范优先于项目默认值；同时满足平台遮挡区与项目文字安全区，取两者安全区域的交集。若交集过小，应重新排版并制作平台版本。

## 2. 通用默认值：横屏、方形及非沉浸式展示

没有专门平台模板时，采用传统保守设置：主体安全区为中央 90%（四边各留 5%）；文字安全区为中央 80%（四边各留 10%）。这是本项目采用的通用制作默认值，不宣称是所有平台或所有广播交付的强制标准。

| 画布 | 主体边距：左 / 右 / 上 / 下 | 文字边距：左 / 右 / 上 / 下 |
| --- | --- | --- |
| 横屏 1920×1080 | 96 / 96 / 54 / 54 px | 192 / 192 / 108 / 108 px |
| 横屏 3840×2160 | 192 / 192 / 108 / 108 px | 384 / 384 / 216 / 216 px |
| 方形 1080×1080 | 54 / 54 / 54 / 54 px | 108 / 108 / 108 / 108 px |
| 4:5 画布 1080×1350 | 54 / 54 / 67.5 / 67.5 px | 108 / 108 / 135 / 135 px |
| 3:4 画布 1080×1440 | 54 / 54 / 72 / 72 px | 108 / 108 / 144 / 144 px |

- 分数像素的边距向上取整。其他分辨率按相同比例计算。
- 例如 1920×1080 横屏：重要文字的完整可见边界应满足 x≥192、右边界≤1728、y≥108、下边界≤972。
- 字幕也适用文字安全区；多行字幕以整个字幕块的底边判断，不能只检查第一行或文字基线。
- 电视、影院或品牌交付如有单独技术规范，应按其规定校准，不把以上传统默认值当作最新广播标准。

## 3. 9:16 竖屏：项目保守起始配置

平台未指定、需要多平台复用，或暂时无法取得当前版位模板时，先使用以下配置布局，再按目标平台预览校准。

以 1080×1920 为基准，关键文字、Logo、联系方式及主要面部展示区域采用：

| 边缘 | 预留边距 |
| --- | --- |
| 左 | 120 px |
| 右 | 200 px |
| 上 | 300 px |
| 下 | 680 px |

对应安全矩形：x=120～880、y=300～1240，宽 760、高 940 px。其他 9:16 分辨率：左右边距乘以实际宽度/1080，上下边距乘以实际高度/1920，向上取整。

这是本项目主动选择的保守起点，不是任何平台公布的统一标准，也不保证覆盖所有设备、长文案、广告按钮、购物挂件或直播组件。画面主体的非关键部分和背景无需挤进该矩形。不能为塞入安全框而把文字缩小到难以阅读；应优先换行、精简、分镜或拆分平台版本。

## 4. 常见平台如何选用

| 平台 / 场景 | 本项目采用方式 | 官方依据与限制 |
| --- | --- | --- |
| 个人网站、普通横屏展示、YouTube 普通横屏、B站横屏 | 先用第 2 节：主体四边各 5%、文字四边各 10% | 本项目默认值；仍需检查播放器控件、平台字幕和弹幕的遮挡，不声称平台统一强制此数值 |
| 抖音 9:16 | 先用第 3 节：左120、右200、上300、下680 px | 当前未核实适用于所有抖音内容的官方固定四边值；根据发布界面的账号、文案、右侧按钮和挂件校准。不能直接把 TikTok 模板当作抖音模板 |
| 快手 9:16 | 先用第 3 节相同配置 | 属于项目默认值；按当前快手发布预览、按钮和商业挂件校准 |
| 微信视频号 9:16 | 先用第 3 节相同配置 | 属于项目默认值；检查底部账号、描述、互动控件、商品或链接卡片 |
| 小红书 9:16 视频 | 先用第 3 节相同配置 | 属于项目默认值；检查播放页与信息流裁切。3:4 视频按实际画布另排，不能直接套用 9:16 像素 |
| B站竖屏 / 沉浸式播放 | 先用第 3 节相同配置 | 属于项目默认值；另查互动栏和弹幕，不沿用横屏控件位置 |
| YouTube Shorts 普通内容 | 先用第 3 节相同配置，按实际 Shorts 界面调整 | 下行 Google 官方数值来自视频广告模板，不能宣称是所有普通 Shorts 的固定标准 |
| YouTube 9:16 视频广告 | 官方基准模板约为左48、右192、上288、下672 px；与项目文字安全区取交集 | 来自 Google 官方竖屏视频广告安全区模板；具体广告格式、CTA和设备需再核对 |
| TikTok 信息流广告 | 用官方对应画幅、文案长度与挂件类型的安全区文件；模板未取得时先用第 3 节 | 官方明确安全区随画幅、广告文案长度和附加格式变化；标准版与带 Anchor 版不同，没有一个固定四边值适用于所有情况 |
| Instagram / Facebook Reels | 先用第 3 节配置，并核对当前版位模板 | 已核实的 Meta Reels 广告指南要求底部 35% 避放关键元素，即 1080×1920 的底部 672 px；项目另保留更大的上、左右边距。这不是所有自然内容的统一官方标准 |
| Instagram / Facebook Stories | 暂用第 3 节配置，再按 Stories 对应版位预览调整 | 不把 Reels 广告安全区直接宣称为 Stories 通用标准；链接贴纸、账号栏与广告 CTA 需要单独检查 |

- 有精确官方模板时，应保留其不规则遮挡形状；不能只用一个看似宽松的矩形替代。
- 普通发布、广告投放、搜索结果、个人主页封面和直播是不同场景，不互相套用规范。
- 有长描述、声明、商品卡片、下载按钮等附加组件时，增加避让范围，以该组件实际遮挡为准。
- 无法获取平台预览时，继续制作可审阅版本，并明确记录采用的项目默认值与尚未核验的版位；不得声称已完成平台实机验收。

## 5. Remotion 执行规则

1. 在项目中集中定义安全区配置（例如 `safe-area.ts`），至少区分通用横屏与竖屏平台预设；从 Composition 的实际 width、height 计算，避免散落硬编码边距。
2. 关键图文的坐标相对安全矩形排版。检查完整渲染后的可见边界，包括文字字形、描边、Logo、二维码留白、缩放和旋转后的边界，不能只检查定位点或容器。
3. 标题、字幕、CTA和联系入口均受安全区约束。默认不添加任何四角角标，具体遵循第 6 节；必要的品牌或联系信息应融入主体内容并满足文字安全区。
4. 预览应能切换安全区辅助线和目标平台遮挡蒙版。辅助线只用于检查，最终成片默认不包含辅助线或蒙版；除非用户明确要求导出检查版。
5. 检查动画全过程，尤其是弹簧过冲、推拉缩放、视差和转场重叠。关键内容在需要被阅读、辨认的整个展示期间都必须完整处于安全区；有意的入场、退场运动不能造成关键展示阶段被截断。
6. 按 16:9、9:16、1:1、4:5 或 3:4 分别排版。不能简单缩放或居中裁切横屏成片就声称完成竖屏适配。
7. 字幕一般放在文字安全矩形的下部，并给多行文字、阴影和面部留空间；不能固定贴近整张画布的底部。
8. 如必须进行裁切，先计算目标画幅的可见矩形，再对该可见矩形计算安全区，最后换算回源画布坐标。
9. 制作时展示关键场景的安全区检查预览。只有用户要求渲染或导出时才导出整片；导出前再次确认辅助线关闭。

## 6. 画面与导出硬性要求

### 不要四周的角标

- 默认禁止在左上、右上、左下、右下四角或沿画面边缘添加常驻角标、装饰性字标、页码、章节编号、英文标语、日期、水印、制作署名或边缘进度条。即使它们位于安全区内，也不要添加。
- Logo、姓名、标题和联系方式如为视频主题所需，应在主体版式或片头片尾作为正式内容呈现，不做四角常驻标识。只有用户明确要求时，才添加指定角标。

### 正式导出不低于 1080p

- 正式成片必须保持正确画幅，实际输出短边至少 1080 像素：16:9 至少 1920×1080，9:16 至少 1080×1920，1:1 至少 1080×1080，4:5 至少 1080×1350，3:4 至少 1080×1440。允许更高分辨率。
- Composition 从对应的合格分辨率开始制作。正式导出使用完整分辨率，不能用缩放参数把短边降到 1080 以下；不把低清素材或低清预览简单放大后当作高质量成片。
- 内部预览或静帧检查可以降低分辨率以节省时间，但必须标明其为预览，不能作为正式成片交付。
- 导出后读取视频文件的实际宽高确认达标，不能只检查 Composition 配置或文件名。

### 使用苹果自带的编码器

- 在 macOS 上导出时，必须通过苹果 VideoToolbox 硬件编码。默认交付 H.264 / MP4，对应编码器为 `h264_videotoolbox`；用户指定 HEVC 时使用 `hevc_videotoolbox`。
- Remotion CLI 明确设置 `--codec=h264 --hardware-acceleration=required`；调用 `renderMedia()` 时设置 `codec: 'h264'` 和 `hardwareAcceleration: 'required'`。不要使用允许悄悄回退软件编码的 `if-possible`。
- 使用与当前 Remotion 版本兼容的硬件编码参数。通过 `--video-bitrate` 控制码率，不能沿用与该模式冲突的 `--crf`、`--x264-preset` 或其他仅用于软件编码的设置。1080p H.264 的项目起始码率为 16 Mbps，根据帧率、动态复杂度及更高分辨率提高，并检查实际画质。
- 导出命令示例（先将入口、合成 ID 和输出路径替换为项目实际值，并确认 Composition 的短边至少 1080）：

```bash
npx remotion render src/index.ts CompositionId out/video.mp4 --codec=h264 --hardware-acceleration=required --video-bitrate=16M --pixel-format=yuv420p
```

- 检查实际生效的导出命令、项目脚本和配置，清理冲突参数；核实编码日志使用了 VideoToolbox。文件只标注 H.264 或 HEVC，并不能证明使用了苹果编码器。
- 苹果硬件编码不可用时，先排查设备、Remotion 版本和参数；如仍不可用，明确报告原因，不擅自切换到软件编码或其他厂商编码器。
- VideoToolbox 加速的是视频编码阶段；不要据此声称所有 React 场景和浏览器逐帧渲染均由苹果编码器完成。

## 7. 交付前检查

- 检查每个场景的首尾、关键停留帧、动画过冲点及转场，并完整播放检查。
- 确认没有未经用户要求的四角角标或边缘装饰信息；正式成片短边至少 1080，且编码日志确认使用了苹果 VideoToolbox。
- 确认标题、字幕、Logo、人物面部、联系方式和二维码没有被画布、平台界面或其他图层意外遮挡。
- 使用目标平台的官方模板或当前发布预览校准；没有平台实机条件时如实说明，不能用 Remotion Studio 预览代替平台实机验证。
- 发现越界时，优先移动、换行、精简内容或调整分镜，再考虑适度缩小字号；不为保留装饰排版牺牲可读性。
- 交付时简要注明画幅、安全区预设及验证范围，不把“能在 Studio 播放”当作安全区验收。
